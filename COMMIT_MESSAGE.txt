refactor: migrate from global window variables to Svelte store-based architecture

This commit refactors the application to use Svelte stores for state management
and component communication, replacing global window variables and direct DOM
manipulation with reactive patterns.

Major changes:
- Remove Init utility class and consolidate initialization in scripts.js
- Replace window.musicPlayer with stores.music.musicPlayer for reactive access
- Move script initialization from App.svelte to Splashscreen.svelte to ensure
  audio element exists before initialization
- Add musicPlayer and controller instances to stores for component access
- Implement reactive folio visibility management via stores.navigation.folioVisibility
- Replace getMusicElements() helper with direct element bindings (bind:this)
- Remove direct querySelector calls in favor of reactive store subscriptions

Component improvements:
- About.svelte: Use bind:this for scroll element instead of querySelector
- Footer.svelte: Remove window.musicPlayer fallbacks, use store directly
- SplashSound.svelte: Access musicPlayer reactively from store
- Rubrics.svelte: Make rubric focus updates fully reactive
- Folios.svelte: Add reactive folio visibility management based on store
- Websites.svelte: Switch from global store to local component state
- Folio components (AnimFolio1, Gridz, MusicFolio1, MusicPlaylistFolio):
  Replace getMusicElements() with store-based musicPlayer access

New features:
- Add appAPI module for console debugging and external access
- Expose appAPI to window.app for development tools

Files changed: 17 files modified, 1 file deleted
- Removed: src/utils/init.js
- Added: src/utils/api.js
- Modified: Multiple components and utilities to use store-based architecture

This refactoring improves maintainability, reduces coupling, and makes the
codebase more aligned with Svelte's reactive patterns.
